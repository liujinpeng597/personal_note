## Context

当前目录 `personal_node/` 只有三份输入素材，没有任何代码、构建脚本或版本控制历史，属于全新项目：

- `个人笔记提示词.md`：功能清单（主页、注册、登录、个人主页、笔记管理、分享、评论、收藏、关于、Markdown 渲染）、技术栈（前端 html+js+css / 后端 Python+Flask / 数据库 SQLite）、两条硬性规范（统一 `{code, message}` 错误信封并以中文 message 提示用户；依赖使用国内镜像并锁定版本）。
- `个人笔记主页.jpg`（2560×1440）：不是 UI 设计稿，而是一张**摄影主视觉**——明亮白色桌面、斑驳树叶光影，右侧有米白马克杯（杯身一颗小爱心）、插满天星的玻璃瓶、摊开的线圈笔记本（压着一片绿叶）与一支笔，右上角垂着绿叶；**左半幅约 55% 宽度几乎全是亮留白**。
- `个人笔记-笔记背景.jpg`（1666×944）：**做旧羊皮纸**材质，手撕毛边、深色暗角、左上与右下古典藤蔓角饰、右上淡罗盘玫瑰、左下褪色羽毛笔与隐约字迹。

要解决的问题：把这份提示词落成一个能真实跑起来的个人笔记 Web 应用，并让两张素材承担明确、不冲突的视觉角色。两张图调性一明一旧，是本设计最主要的视觉约束——处理方式见「界面设计契约」。

本机环境实测（影响启动方式与文档写法）：

- Python **3.12.3**，经 `py -3.12` 调用；`python` 与 `pip` **未加入 PATH**。
- pip **24.0**，**未配置任何镜像**（`%APPDATA%\pip\pip.ini` 不存在）。
- pip 访问 `pypi.org` 正常（可列出 Flask 最新 3.1.3）；访问清华镜像 `pypi.tuna.tsinghua.edu.cn` 在本机连续两次无响应。因此文档把国内镜像写为首选命令，同时给出回退与 `pip.ini` 配置方法，**不假设镜像一定可达**。

## Goals

1. 实现提示词中的全部功能：主页、注册、登录、个人主页、笔记管理（写 / 存草稿 / 列表 / 详情）、分享（链接 + 可选密码）、评论、收藏、关于页、Markdown 渲染。
2. 严格遵守两条规范：所有写操作返回 `{ "code": ..., "message": "中文提示" }` 且前端展示该 message；依赖写进 `requirements.txt` 锁定版本，安装命令默认走国内镜像。
3. 主页使用 `个人笔记主页.jpg` 作 Hero 主视觉（文案落在照片左侧留白），笔记详情/编辑页使用 `个人笔记-笔记背景.jpg` 作正文纸张底；全站不依赖任何外链图片、字体或 CDN。
4. 一条命令启动（`start.bat`），首次运行自动建库，可在本机离线（仅首次装依赖需网络）完整演示全部功能。
5. 提供 pytest 冒烟测试覆盖主流程与关键安全边界。

## Non-Goals

- 深色模式、笔记导出 PDF/Word、富文本编辑器、多人协同编辑。
- 邮箱验证、找回密码（需外部邮件服务）。
- 公开笔记广场、他人笔记浏览（访客只能通过分享链接看到单篇笔记）。
- 社交关系（关注/私信）、通知系统、移动 App。
- 生产部署形态（Gunicorn/Nginx/Docker/HTTPS）、备份与运维脚本。
- 登录限流、验证码、内容审核队列。
- 最近浏览记录表（已确认「笔记历史」= 我发表过的笔记时间线）。

## Recommended Approach

**Flask 3 + Jinja2 服务端渲染页面，交互就近用原生 `fetch` 调 JSON 接口，SQLite 经 Flask-SQLAlchemy 访问，Markdown 服务端渲染后用 nh3 消毒，前端零第三方依赖。**

选它的理由：

- 直接满足规范一：页面由 Jinja2 渲染，写操作统一返回 `{code, message, data}`，前端一个 `request()` 封装 + 一个 `toast()` 就把所有中文提示落地，不需要为每个接口手写一套 DOM 拼接。
- 直接满足规范二与"前端 html + js + css"：前端不发包、不引 CDN，只写 `static/css`、`static/js` 和 Jinja 模板；Python 侧的第三方库全部用 `==` 锁进 `requirements.txt`。
- Markdown 放服务端渲染 + nh3 白名单消毒，XSS 只在一个函数里防守，前端拿到的预览 HTML 已经是安全的。
- 用户已明确确认：页面生成方式选服务端渲染，数据层选 ORM。

## Alternatives Considered

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Jinja2 SSR + 就近 `fetch` JSON 接口 | 中文错误提示规范最易落地；无前端依赖；Jinja 自动转义兜住 XSS | 局部刷新要自己写少量 JS | **采用** |
| 纯静态 `.html` + JS 调 API 拼 DOM | 更贴近"前端 html+js+css"的字面理解；前后端边界清晰 | 展示逻辑要在 JS 里重写一遍，代码量约翻倍；字符串拼 DOM 时转义靠自觉，XSS 风险高；首屏空窗 | 否决 |
| Flask + HTMX 局部替换 | 交互 JS 最省 | 多一个前端依赖，与"前端零依赖 + 锁定依赖"的取向不符 | 否决 |
| 标准库 `sqlite3` 手写 SQL | 零额外依赖，SQL 全显式 | 7 张表含两组多对多与级联删除，手写 JOIN/事务代码显著变多 | 否决（用户已选 ORM） |
| 前端 `marked.js` 渲染 Markdown | 预览零延迟 | 需自行处理 XSS，且要么引 CDN（本机镜像都不通，外网更不可靠）要么本地 vendored，与"前端零第三方依赖"冲突 | 否决（用户已选服务端渲染） |

### 依赖与版本锁定

运行依赖（`requirements.txt`，全部 `==`）。下表是**初始锁定候选值**：本机 pip 访问 `pypi.org` 时通时不通（能列出 Flask 最新 3.1.3，随后同一命令挂起），因此这几个版本号**尚未逐一实测解析成功**，实施第一步必须按下方「锁定规则」校验并回填最终值：

| 包 | 初始锁定候选 | 用途 |
|----|--------------|------|
| Flask | 3.0.3 | Web 框架（含 Jinja2、Werkzeug、itsdangerous、click） |
| Flask-SQLAlchemy | 3.1.1 | ORM 集成 |
| SQLAlchemy | 2.0.36 | ORM（显式锁定，避免随 Flask-SQLAlchemy 漂移） |
| Markdown | 3.7 | Markdown → HTML |
| nh3 | 0.2.18 | HTML 白名单消毒（防 XSS） |

开发依赖（`requirements-dev.txt`）：pytest 8.3.3。

备选：若 `nh3` 在目标镜像上无 Python 3.12 轮子而安装失败，改用纯 Python 的 `bleach==6.1.0`（接口封装在 `utils/markdown_render.py` 内，替换成本为一处）。

**锁定规则**（写进 README）：安装前用 `py -3.12 -m pip index versions <包> -i <镜像>` 校验表内版本是否可用；若不可用，取该包**最新可用补丁版**并同步更新 `requirements.txt` 与本表，不允许使用范围约束安装后放任漂移。安装命令：

```
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

镜像不可达时回退：`-i https://mirrors.aliyun.com/pypi/simple/` 或省略 `-i`（走 pypi.org）。永久配置写入 `%APPDATA%\pip\pip.ini` 的 `[global] index-url`。

### 配置

- `SECRET_KEY`：优先读环境变量 `NOTES_SECRET_KEY`；否则读 `instance/secret_key`（首次启动自动用 `secrets.token_urlsafe(32)` 生成并写入）。
- `SQLALCHEMY_DATABASE_URI`：`sqlite:///<项目根>/instance/notes.db`。
- `MAX_CONTENT_LENGTH`：2 MB（上传）。
- 会话 Cookie：`SESSION_COOKIE_HTTPONLY=True`、`SESSION_COOKIE_SAMESITE='Lax'`、非 permanent（关闭浏览器即失效，供分享密码的"本次会话有效"语义复用）。

## 数据模型

7 张表，SQLite 单文件 `instance/notes.db`。

**users**

| 字段 | 类型 | 约束 |
|------|------|------|
| id | INTEGER | PK |
| username | VARCHAR(32) | UNIQUE NOT NULL，3–20 字符，允许中英文、数字、下划线 |
| email | VARCHAR(120) | UNIQUE NOT NULL，小写归一化后存储与查重 |
| password_hash | VARCHAR(255) | NOT NULL，`generate_password_hash`（scrypt） |
| avatar_url | VARCHAR(255) | NULL |
| bio | VARCHAR(200) | NULL |
| created_at | DATETIME | NOT NULL，默认当前时间 |

**notes**

| 字段 | 类型 | 约束 |
|------|------|------|
| id | INTEGER | PK |
| user_id | INTEGER | FK users.id，NOT NULL，索引 |
| title | VARCHAR(120) | NOT NULL，去空白后非空 |
| content_md | TEXT | NOT NULL，Markdown 原文（不存渲染结果） |
| status | VARCHAR(10) | NOT NULL 默认 `draft`，取值 `draft` / `published`，索引 |
| created_at / updated_at | DATETIME | NOT NULL |
| published_at | DATETIME | NULL，首次发布时写入 |

**tags**：`id` PK、`name` VARCHAR(20) UNIQUE NOT NULL（去空白、小写归一化）。
**note_tags**：`note_id` + `tag_id` 复合主键，两侧 FK。
**favorites**：`id` PK、`user_id` FK、`note_id` FK、`created_at`，`UNIQUE(user_id, note_id)`。
**comments**：`id` PK、`note_id` FK（索引）、`user_id` FK、`content` VARCHAR(500) NOT NULL、`created_at`。
**shares**：`id` PK、`note_id` FK **UNIQUE**（一篇笔记同时只有一个有效分享）、`token` VARCHAR(32) UNIQUE NOT NULL、`password_hash` VARCHAR(255) NULL、`created_at`、`revoked_at` DATETIME NULL。

规则：

- 笔记删除时级联删除其 `note_tags` / `favorites` / `comments` / `shares`（`cascade="all, delete-orphan"`）。
- 笔记只能处于 `draft` / `published` 两态，且**只升不降**（不做"已发布转回草稿"）；**草稿不可分享**（分享按钮只在已发布的笔记上出现）。
- `/u/<username>` 一律只展示该用户的**已发布**笔记，作者本人访问自己的主页也一样（自己的草稿只在 `/notes?tab=draft` 里看）。
- 分享 = 生成 token（`secrets.token_urlsafe(16)`）；"取消分享"置 `revoked_at`，链接随即失效，保留历史行。重新分享生成新 token 并清空 `revoked_at`。
- 用户删除账号不在本期范围（Non-Goal），故用户不使用级联删除。

## 接口契约

### 响应信封（规范一）

成功：`{"code": "OK", "message": "操作成功", "data": {...}}`，HTTP 200/201。
失败：`{"code": "ERR_<原因>", "message": "中文提示"}`（原因取下方错误码表），HTTP 状态码语义化。

| code | HTTP | 中文 message 示例 | 触发场景 |
|------|------|-------------------|----------|
| `OK` | 200/201 | 操作成功 / 已保存草稿 / 已发布 / 已收藏 | 成功 |
| `ERR_VALIDATION` | 400 | 请输入邮箱 / 两次输入的密码不一致 / 标题不能为空 | 字段校验失败，`data.fields` 带字段级错误 |
| `ERR_EMAIL_TAKEN` | 409 | 该邮箱已被注册 | 注册查重 |
| `ERR_USERNAME_TAKEN` | 409 | 该用户名已被使用 | 注册查重 |
| `ERR_BAD_CREDENTIALS` | 401 | 邮箱或密码不正确 | 登录失败（不区分哪个错） |
| `ERR_UNAUTHORIZED` | 401 | 请先登录 | 未登录访问受保护接口 |
| `ERR_FORBIDDEN` | 403 | 你没有权限执行该操作 | 越权写操作 |
| `ERR_CSRF` | 403 | 页面已过期，请刷新后重试 | CSRF token 缺失/不匹配 |
| `ERR_SHARE_PASSWORD` | 403 | 密码不正确，请重试 | 分享密码校验失败 |
| `ERR_NOT_FOUND` | 404 | 内容不存在或已被删除 | 笔记/用户/分享不存在，或非作者访问他人笔记 |
| `ERR_SHARE_REVOKED` | 410 | 该分享链接已失效或已被作者取消 | 访问已撤销的分享 |
| `ERR_FILE_TYPE` | 415 | 仅支持 JPG、PNG、GIF、WebP 图片 | 上传类型不符 |
| `ERR_FILE_TOO_LARGE` | 413 | 图片不能超过 2 MB | 上传超限 |
| `ERR_SERVER` | 500 | 服务器开小差了，请稍后再试 | 未捕获异常（细节只进服务端日志） |

约定：`data.fields` 形如 `{"email": "该邮箱已被注册"}` 供前端就近标红；前端 `request()` 统一 `toast(res.message)`，若存在 `fields` 则同时标记对应输入框。页面级 GET 失败用 Jinja flash 呈现同一套中文文案。

## Interface Design Contract

### Experience and Journeys

**目标用户与场景**：一个人、一台电脑、想安静记点东西。使用场景多在清晨或夜晚的自有书桌前，写的是私人内容，偶尔把某一篇发给一两个朋友看。

**体验目标**：打开主页像走进清晨的书桌；写笔记像在旧纸上落笔；阅读自己的笔记时有"这是我的私人纸页"的确定感。界面只干一件事——让人愿意写下第一行，并能安全地把它藏起来或递出去。

**主导航**：顶栏常驻。未登录：左侧品牌「个人笔记」，右侧「登录」「注册」。已登录：左侧品牌 + 「我的笔记」，右侧一个主按钮「写笔记」，以及头像菜单（个人主页 / 设置 / 退出）。

**主要旅程**

1. 首次访问 → 主页 Hero 读一句话 → 点「开始记录」→ 注册 → 自动登录 → 落到空列表 → 空状态引导「写第一篇笔记」→ 编辑器 → 写下标题正文 → 「发布」→ 详情页看到自己的一页纸。
2. 二次访问 → 登录 → 我的笔记（全部/草稿/已发布 + 搜索 + 标签）→ 点开草稿继续写 → 存草稿或发布。
3. 分享 → 详情页点「分享」→ 无密码或设密码 → 复制链接 → 朋友打开：无密码直接读；有密码先输密码（本次会话内不再重复问）→ 朋友登录后可评论。
4. 收藏 → 在详情页点杯上那颗小爱心 → 个人主页「收藏」tab 里回看。
5. 整理 → 详情页「编辑」改标题/正文/加标签 → 保存 → 列表按更新时间倒序。
6. 收回 → 详情页「取消分享」→ 朋友再打开看到「该分享链接已失效或已被作者取消」。

**恢复路径**：任何写操作失败都在原地保留用户输入（不刷新、不清空），toast 显示中文原因并在出错字段标红；未登录时任何受保护入口都跳到登录页，登录后回到原目标页；404/410 页面提供「回到我的笔记」或「回到主页」出口。

**信息层级**：一页只有一个 h1；页面主体先给内容（笔记正文、Hero 文案），再给次级操作（分享/收藏/标签），破坏性操作（删除笔记、取消分享、删除评论）收在菜单或次要按钮里并要求二次确认。

### Visual System

**方向与理由**：素材本身给了答案——主页是明亮自然的现代摄影，笔记背景是复古羊皮纸。硬把两者混在一起会显得脏，因此**按区域分工**：全站外壳（顶栏、列表、表单、页脚）保持干净清新的浅色纸质调，只有「正文」这一件事被放进那张旧纸里，形成"现代书桌 + 一张旧纸"的明确对比。视觉力气只花在一处（签名元素），其余控件一律克制。

**设计变量**（全部取自两张素材，供 `static/css/tokens.css` 定义）

| `--shell` | `#F5F1EA` | 主页照片的亮桌面：页面底色 |

**签名元素**：笔记详情/编辑页的「一张真纸」——`static/img/paper.jpg` 直接作纸张底（`background-size: 100% 100%`、`background-repeat: no-repeat`），正文区 inset 留白避开手撕毛边与藤蔓角饰，正文用 `--ink` 墨色，行高 1.9、字号 17px，中文正文用衬线字体栈，让"旧纸"的复古感只出现在这一处。全站第二处情感化细节是收藏按钮——复用杯上那颗爱心的形状与 `--heart` 颜色，未收藏为 1.5px 描边，已收藏为实心。

**排版**：中文界面，系统字体栈，**不引入任何 webfont**。标题：`"Georgia", "Times New Roman", "Songti SC", "SimSun", serif`；正文与控件：`-apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif`。字号阶梯：Hero 标题 44/32/28（桌面/平板/移动），h1 30，h2 22，正文 16，元信息 13。行高：标题 1.3，正文 1.7。

**形状与阴影**：卡片圆角 10px，按钮/输入框 6px，标签 chip 999px；阴影只两级——`0 1px 2px rgba(59,50,41,.06)`（默认）与 `0 8px 24px rgba(59,50,41,.08)`（hover/浮层）。不使用玻璃拟态、大圆角、装饰性渐变。

**动效**：仅两处，均为 150ms `ease-out`——按钮 hover 的底色过渡、卡片 hover 的阴影加深。无滚动视差、无入场动画；`prefers-reduced-motion: reduce` 时全部过渡时长归零。

**素材策略**：两张素材复制为 `static/img/hero-desk.jpg`（2560×1440，不压缩不裁剪）与 `static/img/paper.jpg`。图标用内联 SVG（笔画 1.5px、`currentColor`），不引图标库。头像默认用用户名首字母 + `--leaf` 圆形底，用户可填图片 URL 或上传。无任何外链资源。

### Accessibility and Visual Verification

- 语义结构：`header / nav / main / article / footer`；每页唯一 `h1`；笔记正文用 `<article>`，评论区用 `<section aria-label="评论">`。

- 触摸：所有可点目标 ≥ 40×40px；移动端抽屉打开时锁定页面滚动。
- 图片替代文本：Hero `alt="清晨书桌上的咖啡杯、花瓶与摊开的笔记本"`；纸张背景为装饰性 CSS 背景，不承载信息。
- 视觉验证目标（实现后逐项截图核对）：`/` 在 1440×900 与 390×844；`/notes` 空状态、有内容、搜索无结果；`/notes/<id>` 纸张版式与长正文换行；`/notes/<id>/edit` 桌面分栏与 390 宽切换；`/s/<token>` 无密码页、密码页、密码错误、已失效；`/u/<name>` 资料卡与两个 tab；一处 500 错误页与一处 404 页。

## Data Flow

**发布一篇笔记**：编辑器（标题 + `textarea` + 标签）→ 点「发布」→ 新笔记先 `POST /notes`（`status=draft`）拿到 `id`，再 `POST /notes/<id>/publish`；已存在的草稿直接调 `/publish`。后端校验登录、所有权、标题非空、正文非空、标签数量 ≤ 5 且每个 ≤ 20 字 → 失败：`fail("ERR_VALIDATION", "标题不能为空", fields=...)` → 前端 `toast(message)` 并把 `fields` 标红，页面不刷新，输入保留 → 成功：`{"code":"OK","message":"已发布","data":{"url":"/notes/12"}}` → 前端跳转详情页。点「存草稿」则只走 `POST /notes` 或 `PUT /notes/<id>`，不调用 `/publish`。

**阅读一篇笔记**：`GET /notes/12` → 后端确认存在且 `user_id == session.user_id`（否则 404）→ 模板拿到 `note`，正文经 `render_md` 过滤器输出安全 HTML → 纸张容器内渲染 → 评论与收藏状态由同一次查询带出（避免额外请求）。

**实时预览**：`textarea` 输入 → 300ms 防抖 → `POST /api/preview {content_md}` → 服务端渲染 + 消毒 → `{"code":"OK","data":{"html": "..."}}` → 前端仅 `innerHTML` 写入预览区（内容已消毒）。

**分享访问**：作者点「分享」→ 可选设密码 → `POST /notes/<id>/share` → 后端生成 `token = secrets.token_urlsafe(16)`，`password_hash` 有密码时用 `generate_password_hash` 存储 → 返回完整链接 → 访客 `GET /s/<token>` → 若 `revoked_at` 非空返回 410；若 `password_hash` 为空直接渲染；否则先渲染密码页 → `POST /s/<token>/unlock` 校验成功后在 session 写入 `share_ok:<token> = true`（会话级，非 permanent）→ 重定向回 `GET /s/<token>` 正常展示。

**上传图片**：编辑器点插入图片 → `POST /api/upload`（multipart）→ 校验通过 → 存 `static/uploads/<uuid>.<ext>` → 返回 `{"code":"OK","data":{"url":"/static/uploads/xxx.png"}}` → 前端在光标处插入 `![图片](/static/uploads/xxx.png)`。

**收藏**：详情页点爱心 → `POST /notes/<id>/favorite` → 命中则删除、未命中则插入（唯一约束保证不重复）→ 返回最新 `{favorited, count}` → 前端就地切换爱心与计数，不刷新页面。

## Error Handling

| 失败 | 处理 |
|------|------|
| 字段校验失败 | 400 `ERR_VALIDATION`，`data.fields` 定位到具体字段，前端标红 + toast；输入不丢失 |
| 邮箱/用户名重复 | 409，注册页就地标红 |
| 登录失败 | 401 `ERR_BAD_CREDENTIALS`，统一文案「邮箱或密码不正确」，不区分是哪个错 |
| 未登录访问受保护页面/接口 | 页面 302 跳登录并带 `next`；接口 401 `ERR_UNAUTHORIZED` |
| 越权访问/修改他人笔记 | 一律 404 `ERR_NOT_FOUND`，不区分"不存在"与"无权限" |
| CSRF token 缺失/过期 | 403 `ERR_CSRF`「页面已过期，请刷新后重试」 |
| 分享密码错误 | 403 `ERR_SHARE_PASSWORD`，密码页留在原地并清空输入框 |
| 分享已撤销/不存在 | 410 `ERR_SHARE_REVOKED` 或 404，页面给「回到主页」出口 |
| 上传类型不符 / 超限 | 415 / 413，编辑器保留已输入内容 |
| 数据库异常、模板异常等未捕获错误 | 500 `ERR_SERVER`「服务器开小差了，请稍后再试」，堆栈只写服务端日志，不回传前端 |
| 前端网络失败/接口不可达 | `request()` 捕获后统一 toast「网络异常，请检查连接后重试」 |

## Security

信任边界：浏览器（不可信）↔ Flask 应用（可信）↔ SQLite 文件（本机）。

- **口令存储**：`generate_password_hash`（scrypt），永不存明文，日志不打印口令字段；登录失败不区分账号是否存在。
- **会话**：Flask 签名 Cookie，`HttpOnly` + `SameSite=Lax` + 非 permanent；`SECRET_KEY` 随机生成存 `instance/secret_key`（`.gitignore`），支持环境变量覆盖。
- **CSRF**：所有写请求要求 `X-CSRF-Token`（会话内随机值，经 `<meta>` 注入页面），缺失或不匹配返回 403。
- **越权（IDOR）**：读/改/删笔记、取消分享、删除评论均校验所有权；越权响应与"不存在"不可区分，避免枚举。草稿永不出现在他人可见面。
- **XSS**：Markdown 渲染结果经 nh3 白名单消毒；评论按纯文本存储、模板输出 + CSS `white-space: pre-wrap` 保留换行；Jinja 自动转义全局开启；用户填写的头像 URL 只允许 `http/https` 且经 `url_for` 之外不做拼接。
- **分享安全**：token 用 `secrets.token_urlsafe(16)`（不可枚举）；分享密码同样哈希存储并用 `check_password_hash` 校验；解锁标记只写 session，不写 Cookie 内容；取消分享立即失效；草稿不可分享。
- **上传安全**：白名单 `jpg/jpeg/png/gif/webp` + 魔术字节校验（不信任 `Content-Type` 与文件名）+ `MAX_CONTENT_LENGTH=2MB` + uuid 重命名 + 拒绝 SVG（可执行脚本）+ 上传目录不进版本库。
- **注入**：全部经 ORM 参数化查询，无字符串拼接 SQL；标签按逗号切分后逐项校验长度与数量，避免超长写入。
- **信息泄露**：500 只回中文通用文案；分享页不暴露作者邮箱等私有字段。
- **明确不做**（练习项目定位，Non-Goal）：登录限流、验证码、审计日志、HTTPS、备份。

## Boundaries and Dependencies

- `blueprints/*` 拥有各自的路由与权限校验，**不拥有**跨模块查询逻辑与响应格式；不得互相 import。
- `utils/responses.py` 拥有响应信封与错误码，**不拥有**业务校验。
- `utils/markdown_render.py` 拥有渲染与消毒白名单，是唯一可以把 Markdown 变成 HTML 的地方；**不拥有**缓存或存储。
- `models.py` 拥有表结构与级联规则，**不拥有**业务查询与展示字段决策之外的逻辑。
- `templates/*` 只消费变量，**不拥有**数据访问。
- 外部依赖：Flask / Flask-SQLAlchemy / SQLAlchemy / Markdown / nh3 / pytest（版本见「依赖与版本锁定」）。假设：Python 3.12 可用（已确认 3.12.3）；首次安装可访问某个 PyPI 索引（已确认 pypi.org 可达；国内镜像在本机当前不可达，故 README 给三级回退）；不依赖任何外网运行时资源。
- 素材依赖：两张 JPG 由输入素材复制而来，不改内容；纸张背景以 `100% 100%` 拉伸，需保证正文 inset ≥ 48px 以免压到毛边与角饰（若素材被替换，需重新核对 inset 与正文对比度）。

## Testing

`pytest` + Flask test client，`tests/` 下按模块分文件，运行 `.venv\Scripts\python -m pytest -q`。使用独立的临时 SQLite（`sqlite:///:memory:` 或 `instance/test.db`），每个用例前重建表。

必须覆盖的冒烟与安全用例：

1. 注册 → 登录 → 退出全链路；重复邮箱 409 `ERR_EMAIL_TAKEN`；两次密码不一致 400；邮箱格式非法 400。
2. 未登录访问 `/notes` 302 到登录页；未登录调 `POST /notes` 401 `ERR_UNAUTHORIZED`。
3. 建草稿 → 草稿不出现在他人个人主页、不能分享 → 发布 → 出现在自己列表与个人主页。
4. 越权：用户 B 读/改/删用户 A 的笔记，全部 404；用户 B 取消 A 的分享失败。
5. 分享：无密码链接对匿名访客可见；有密码时匿名访问被拦、密码错误 403、密码正确后同会话可读；取消分享后 410；草稿分享被拒。
6. 评论：登录可发、可删自己的；删除他人的评论 404；未登录发评论 401。
7. 收藏：重复点击为幂等切换，`UNIQUE(user_id, note_id)` 生效，计数正确。
8. Markdown 与 XSS：`<script>alert(1)</script>`、`<img src=x onerror=alert(1)>`、`[x](javascript:alert(1))` 渲染后不含脚本与事件属性；正常标题/列表/代码块/表格/图片语法正常输出。
9. 上传：非图片扩展名 415；伪造 `.png` 但内容非图片被魔术字节拦下 415；超 2MB 413；正常 PNG 返回可用 URL。
10. CSRF：缺少 `X-CSRF-Token` 的写请求 403 `ERR_CSRF`。
11. 统一信封：任取 3 个失败接口断言响应体同时含 `code` 与中文 `message`。
12. 搜索与分页：`?q=` 命中标题/正文/标签；`?page=2` 返回第二页且不重不漏。

手工视觉验证：按「Accessibility and Visual Verification」列出的路由与视口逐一截图核对，确认无外链资源（打开 DevTools Network，除本机外无第三方请求）。

## Rollout

全新项目，无迁移与兼容负担。交付方式：

1. 首次：双击 `start.bat`（内部执行 `py -3.12 -m venv .venv` → 装依赖（镜像，失败回退）→ `flask --app run init-db` 建表 → 启动）。
2. 手工等价命令：`py -3.12 -m venv .venv` → `.venv\Scripts\python -m pip install -r requirements.txt -i <镜像>` → `.venv\Scripts\python run.py` → 浏览器打开 `http://127.0.0.1:5000`。
3. 可选演示数据：`.venv\Scripts\python run.py --demo` 建一个演示账号（用户名 `demo`、密码写进 README）与 3 篇已发布笔记、1 篇草稿、2 条评论，便于演示与截图。
4. 回滚：删除 `instance/notes.db` 与 `.venv` 即为干净状态；上传文件在 `static/uploads/`。
5. `.gitignore`：`.venv/`、`instance/`、`app/static/uploads/`、`__pycache__/`、`.pytest_cache/`。

## Deferred Questions

均带默认值，可在实现或实现计划阶段直接采用，不阻塞开工：

- **头像形态**：默认「上传图片 URL」与「用户名首字母圆底」两者都支持，首字母为首选默认；不做裁剪。
- **列表每页条数**：默认 10；分页控件做上一页/下一页 + 页码。
- **搜索范围与排序**：默认标题 + 正文 + 标签名 LIKE 匹配，`updated_at` 倒序；不做全文索引、不做模糊纠错。
- **标签数量与长度**：默认每篇最多 5 个、每个 ≤ 20 字，超出报 `ERR_VALIDATION`。
- **上传体积上限**：默认 2 MB；如需放宽只改 `MAX_CONTENT_LENGTH` 与前端提示文案。
- **演示数据**：默认提供 `--demo` 且**不自动执行**，由 README 指示。
- **登录限流**：默认不做（Non-Goal）；若要加，建议按 IP + 邮箱计数存内存字典，不引 Redis。
- **`nh3` 安装失败时的替代**：默认切换到 `bleach==6.1.0`，改动集中在 `utils/markdown_render.py`。
- **国内镜像可达性**：默认首选清华镜像；若本机不可达则依次回退阿里云镜像、pypi.org，README 写明，不影响交付物本身。

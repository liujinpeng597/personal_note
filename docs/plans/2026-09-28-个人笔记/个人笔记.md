## Overview

**Goal:** 按已确认的设计文档，实现一个可本地一条命令启动的个人笔记 Web 应用（注册登录、笔记管理、分享、评论、收藏、标签搜索、Markdown 渲染），并让两张素材分别承担主页 Hero 与笔记纸张的视觉角色。

**Architecture:** Flask 3 应用工厂 + Jinja2 服务端渲染页面，写操作就近提供返回 `{code, message, data}` 的 JSON 接口，前端用原生 `fetch` + `toast()` 消费；SQLite 经 Flask-SQLAlchemy 访问；Markdown 在服务端渲染后用 nh3 白名单消毒；前端零第三方依赖，不引外链资源。

**Tech Stack:** Python 3.12.3（`py -3.12`）、Flask 3.0.3、Flask-SQLAlchemy 3.1.1、SQLAlchemy 2.0.36、Markdown 3.7、nh3 0.2.18、pytest 8.3.3、SQLite、原生 HTML/CSS/JS + Jinja2。

## Dependencies

- 阶段是顺序的：P1 是所有阶段的运行时与样式基础；P2 提供主页与页面外壳内的静态内容；P3 提供登录态，P4 及之后依赖它；P5/P6 依赖 P4 的 `notes` 蓝图与 `note_card` 片段；P7 依赖 P4 的发布态与 P3 的登录态；P8 依赖 P4 的编辑器；P9 依赖全部阶段。
- 运行时假设：本机 Python 3.12.3 经 `py -3.12` 可用（已实测）；`python` 与 `pip` 不在 PATH，所有命令用 `.venv\Scripts\python.exe` 显式调用。
- 依赖安装假设：首次可访问某个 PyPI 索引。实测 `pypi.org` 时通时不通，清华镜像在本机不可达，故 P1 T1 含三级回退与版本校验；**这是环境风险，不阻塞计划**（有回退路径）。
- 数据假设：无历史数据，无迁移；`instance/notes.db` 可随时删除重建。
- 素材假设：两张 JPG 位于项目根，P2 T1 负责复制进 `static/img/`；若素材被替换，需重核正文 inset 与对比度。
- 不引入：Docker、Redis、Celery、前端构建工具、CSS 框架、图标库、webfont。

## Deferred Decisions

以下均带安全默认值，实现时按默认执行即可，无需回头确认：

- 头像形态：默认同时支持「图片 URL」与「用户名首字母圆底」，首字母为默认；不做裁剪。
- 列表每页条数：默认 10，上一页/下一页 + 页码。
- 搜索实现：默认标题 + 正文 + 标签名 `LIKE`，`updated_at` 倒序，不做全文索引。
- 标签约束：每篇最多 5 个、每个 ≤ 20 字，超出返回 `ERR_VALIDATION`。
- 上传上限：默认 2 MB，改 `MAX_CONTENT_LENGTH` 即可放宽。
- 演示数据：`--demo` 提供但**不自动执行**，由 README 指示。
- 登录限流：默认不做（Non-Goal）；若要加，按 IP + 邮箱计数存内存字典，不引 Redis。
- `nh3` 安装失败：切换到 `bleach==6.1.0`，改动只在 `app/utils/markdown_render.py`。
- 镜像可达性：首选清华镜像，依次回退阿里云镜像、pypi.org，README 写明。
- 依赖版本：`Flask 3.0.3 / Flask-SQLAlchemy 3.1.1 / SQLAlchemy 2.0.36 / Markdown 3.7 / nh3 0.2.18 / pytest 8.3.3` 为候选值，P1 T1 校验后若不可用，取该包最新可用补丁版并同步更新 `requirements.txt` 与 README。
